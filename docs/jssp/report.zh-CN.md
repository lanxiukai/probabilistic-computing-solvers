# 作业车间调度中的条件 p-bit 更新

[English](report.md)

本报告研究可行优先序上的 GPU 模拟搜索。p-bit 阶段依据原始排程 makespan 的条件概率选择位置排列；经典确定性解码器提供可行时间表和能量，OR-Tools CP-SAT 提供独立参照。当前没有物理 p-bit 器件实测，也不声称胜过强经典调度方法。

独立确认覆盖六个输入、三个新种子和四种方法，共 72 次原始调用及三次固定工作重放。热浴在四个输入上各三次调用均命中参考最优值，并在留出输入 ft10 上表现出优于匹配控制的副本命中分布。两个 Taillard 输入仍未达到参考值，且 CP-SAT 在每个输入上的平均完整时间更短。云端及本地完整原始证据审计均已通过。

## 问题与表示

当前实现覆盖正整数加工时长、每作业每机器恰好访问一次、不可抢占、无释放时间的经典静态 JSSP。目标是在满足工序前序和机器容量约束时最小化 makespan。

设作业数 $J$、机器数 $M$，状态是长度 $L=JM$ 的序列，每个作业标号出现 $M$ 次。某作业的下一次出现对应其下一道工序。追加解码器把操作放在作业就绪与机器就绪时间的较大值处，因此合法序列总能产生可行排程。

GPU 显式保存 one-hot 赋值 $x_{p,j}=1[s_p=j]$、紧凑序列缓存、目标缓存和参与计数。每个副本显式存储 $J^2M$ 个二元条目。这是冗余编码，不代表同样数量的独立自由度或物理器件。副本数、完整编码状态及实际涉及更新的赋值位数分别报告。该原生解码器能量不是时间展开 QUBO。

每一行的和为 1，每个作业列的和为 $M$。单独翻转一位会离开这一受约束状态空间，排列块则同时保持这两个约束。参与计数记录条件块中考虑过的赋值条目，不等于真正发生翻转的条目数。

参与计数覆盖最终返回的执行过程，包括可能保留的截止越界 chunk；质量结果只使用合格前缀，两者的范围分别报告。

## 更新与归因

每步独立于当前状态选择 2 或 4 个不同序列位置，穷举其 $b!$ 种标号排列，按与 $\exp[-\beta(E-E_{\min})]$ 成正比的概率选择候选。重复标号使每个不同排列的重复次数相等，因而不改变它们的相对概率。实现用独立 CPU 解码与原始排程约束核对整数 makespan。

固定温度下，这是可行序列空间上的条件热浴。循环温程用于优化，不据此声称混合时间或平衡采样保证。确定性解码与目标计算属于经典支撑。冷初态通过均匀排列作业多重集合生成，CP-SAT 解不注入其中。

不同优先序可以解码为同一时间表。因此，固定温度的 Boltzmann 解释针对优先序，并在时间表上引入对应的状态重数，不能推断不同时间表本身服从没有重数因子的 Boltzmann 分布。本研究的实测任务是优化。

逆温度 $\beta$ 对应原始整数加工时间单位，不对应计算过程的墙钟秒数。概率使用 FP64 计算。参考 makespan 用于报告和开发选择，不传入能量核、初始化或 CP-SAT 初解提示。

匹配邻域的 Metropolis 和最低能量随机平局下降（`plateau`）保留同样的初始化与位置提议规则。CP-SAT 使用区间变量、作业前序、机器 `NoOverlap` 约束和 makespan 目标，单 worker 执行；可行上界与证明下界分别报告。优于冷随机前缀并不能证明优于这些控制。

Metropolis 与 plateau 使用和热浴相同的 CUDA 实现，CP-SAT 是独立 CPU 参照。

匹配的 Metropolis 控制计算与热浴相同的完整候选集，而专门优化的 Metropolis 求解器可以只计算被提议候选。它用于隔离更新规则的效果，不是优化后的独立 Metropolis 性能基准。

## 基准与测量

六个标准输入来自 [ScheduleOpt 基准库的固定修订](https://github.com/ScheduleOpt/benchmarks/blob/8a6e36ef31263d36975e56fb481e0ba04e188d6f/jobshop/README.md)。下载工具核验原始字节哈希，这不代表获得上游数据再分发许可。该版本参考表为这些输入列出了相等的上、下界。

`ft`、`la`、`ta` 系列分别源自 Fisher–Thompson、Lawrence 和 Taillard。[OR-Library 的 jobshop 索引](https://people.brunel.ac.uk/~mastjjb/jeb/orlib/jobshopinfo.html) 介绍经典输入及 Taillard 生成器；本研究实际使用的字节固定来自上述 ScheduleOpt 路径。

| 输入 | 作业×机器 | 操作数 | 每模型二元条目 | 参考 makespan |
|---|---:|---:|---:|---:|
| ft06 | 6×6 | 36 | 216 | 55 |
| ft10 | 10×10 | 100 | 1,000 | 930 |
| la01 | 10×5 | 50 | 500 | 666 |
| la16 | 10×10 | 100 | 1,000 | 945 |
| ta01js | 15×15 | 225 | 3,375 | 1,231 |
| ta51js | 50×15 | 750 | 37,500 | 2,760 |

固定目录把六个输入均分类为 `toy`：至少一种参照约束规划引擎能在一分钟内证明最优。它们用于建立正确性、可测量优化及编码规模端点，不代表现代 JSSP 的前沿难例。

硬件为单张 NVIDIA GeForce RTX 5090，约 32 GB 显存；CPU 参照在 AMD EPYC 9354 的一个 worker 上执行。锁定环境为 Python 3.14.6、PyTorch 2.13.0+cu130、Triton 3.7.1、OR-Tools 9.15.6755。准备、搜索、证书检查及完整 runner 时间分别记录。PyTorch 峰值 allocated/reserved 不包含全部 CUDA 驱动或 JIT 显存。

只把搜索截止前观察到的已接受状态计入质量。跨过截止的 chunk 保留但不计入。保存逐 chunk 目标曲线、随机数状态、当前/最佳检查点与原始排程证书。固定工作重放不增加独立试验。

完整 runner 时间包含准备、搜索、证书与最终结果输出；外围源码恢复和进程启动另行记录，不包含在这一 runner 计时中。

## 冻结的确认协议

策略在观察三个确认种子 `2026102344`、`2026102345`、`2026102346` 的结果之前冻结。`ft06`、`la16`、`ta51js` 是开发输入；`la01`、`ft10`、`ta01js` 不参与调参，继承对应策略组。全部确认调用使用 append 解码和 `reduce` 实现，不根据确认结果重新选择配置。

| 策略组 | 输入及搜索时限 | 每原生调用副本数 | 块宽度 | 逆温度循环 |
|---|---|---:|---:|---|
| 小组 | ft06：2 秒；la01：5 秒 | 64 | 2 | 1 至 10，周期 1,024 步 |
| 中组 | la16：20 秒；ft10：20 秒；ta01js：30 秒 | 256 | 4 | 0.08 至 4，周期 8,192 步 |
| 大组 | ta51js：45 秒 | 256 | 2 | 固定为 1 |

逆温度按几何级数增加，并在声明步数处重启。同一输入和种子下，热浴与两种 CUDA 控制共享冷初态、解码器、块宽度、副本数、温程参数、chunk 大小、记录频率及名义时限。CP-SAT 使用一个 CPU worker 和相同名义搜索时限。方法顺序随种子轮换。这些比较匹配更新规则并注明资源，不代表硬件相同或各方法均已专门优化。

每完成八步即记录一次观察；每 16,384 步保存当前/最好序列粗快照，并在距离搜索开始或上次检查点写完达到两秒后的下一完整 chunk 保存恢复检查点。记录成本仍计入搜索时间。首次命中时间的分辨率为 chunk；跨越截止的 chunk 保留，但不计入质量。CP-SAT 质量只取时限内回调，最终返回解、最终下界和证明状态分别保留。

每个输入和方法有三次独立调用。副本分布描述一次调用的 ensemble，不增加独立试验数。全部计划调用和未命中均保留在分母中。三个重放对应首个种子的 `ft06`、`la16`、`ta51js` 热浴，固定已完成工作量和合格质量前缀，不增加确认试验。

观察到最明显更新规则收益的是留出输入 ft10：热浴分别有 48、41、38 个副本达到 930，分母均为 256，而匹配控制每次至多两个副本命中。热浴逐调用中位数均为 937，Metropolis 为 960 / 960 / 958，plateau 为 987 / 986 / 983。la16 的热浴中位数为 946 / 946 / 946，两种控制分别为 956 / 956 / 956 和 982 / 982 / 982。这些差异在冻结面板中重复出现，但独立种子仍只有三个。

负结果同样重要。留出输入 ta01js 上，三个种子的热浴最好质量都差于 plateau 和 CP-SAT；热浴中位数始终为 1286，plateau 为 1279.5 / 1286 / 1285。ta51js 上，热浴中位数 3054 / 3052 / 3054.5 优于 Metropolis 的 3074 / 3077 / 3078，并略优于 plateau 的 3058 / 3060 / 3057，但 ensemble 最好值胜负混合：两个种子差于 Metropolis，一个种子差于 plateau。最好值优于本次单 worker、45 秒 CP-SAT 参照，也不足以建立相对经典方法的普遍优势。

CP-SAT 在 18 次调用中的 14 次于声明搜索预算内证明最优。本面板没有越界 incumbent 回调，也没有时限内质量与最终返回代价的差异。四次未证最优调用的最终求解器下界单列：ta01js 种子 2 返回代价 1240、下界 1019，三个 ta51js 调用均返回下界 2760。这些返回下界不被追记为时限内证明；ta01js 的外部目录参考值仍为 1231。

## 完整时间与参与量

下表为三个完整 runner 时间的算术平均值，单位为秒，包含准备、实测搜索、证书检查及最终输出。三个精确时间和分阶段计时均保留在链接的调用数据中。CP-SAT 使用一个 worker，不是副本集合。

| 输入 | 热浴，GPU | Metropolis，GPU | Plateau，GPU | CP-SAT，CPU |
|---|---:|---:|---:|---:|
| ft06 | 3.698 | 3.685 | 3.663 | 0.400 |
| la01 | 6.861 | 6.886 | 6.802 | 0.430 |
| la16 | 23.514 | 23.051 | 22.781 | 1.512 |
| ft10 | 23.760 | 23.124 | 22.833 | 17.961 |
| ta01js | 34.058 | 33.491 | 33.194 | 24.905 |
| ta51js | 50.687 | 50.539 | 50.943 | 45.443 |

这里每个输入的热浴平均完整时间都长于 CP-SAT。尤其是，ft10 上更好的副本命中分布并不代表相对 CP-SAT 更快的端到端求解。搜索预算与完整时间不能混用。

参与掩码记录直到最终返回 chunk 为止，在条件块中考虑过的赋值项。只使用公开核心数据计算严格质量前缀的参与下界时，从各副本最终计数中减去每个被排除更新最多 $b^2$ 项，再与零取最大值。它是保守下界，不是合格前缀的精确计数，也不是翻转次数。

| 输入 | 每副本编码条目 | 返回参与最小值，种子 1 / 2 / 3 | 合格前缀下界，种子 1 / 2 / 3 |
|---|---:|---|---|
| ft06 | 216 | 216 / 216 / 216 | 184 / 184 / 184 |
| la01 | 500 | 500 / 500 / 500 | 468 / 468 / 468 |
| la16 | 1000 | 1000 / 1000 / 1000 | 872 / 872 / 872 |
| ft10 | 1000 | 1000 / 1000 / 1000 | 872 / 872 / 1000 |
| ta01js | 3375 | 3375 / 3375 / 3375 | 3247 / 3247 / 3247 |

每个最小值都覆盖该调用的全部副本。因此，大例在合格前缀中确实让每副本超过 32,768 个赋值项参与，但仍未达到调度最优值。其三个热浴调用的 PyTorch 峰值为 allocated 105.88 MiB、reserved 170 MiB，对应 256 个副本。这些指标不是物理 p-bit 数量，也不是整个设备的显存或能耗测量。

公开曲线保留任一副本最好值改善点、资格边界和首末观察，保留原始观察序号与缩减元数据；省略的当前状态波动无法从较小曲线还原。完整原始轨迹另行保存。

## 局限

本实现是在可行表示上计算精确原始目标，包含经典解码支撑。它未展示相对 CP-SAT 的调度加速、工业规模竞争力、量子优势或 p-bit 器件节能。追加表示和随机位置邻域尚未利用强 JSSP 局部搜索中的关键路径与关键块结构。更大的编码本身不能证明更有价值的求解规模。

本研究只评估三个新种子及六个目录分类为 toy 的实例。ensemble 最好质量、逐副本命中比例和完整时间回答不同的问题，任何一项都不足以建立普遍优势。本轮未复现关键块禁忌搜索或所引基准框架中的学习方法。时间展开 QUBO 和量子退火文献使用不同表示及硬件，因此不推断跨论文速度比。全状态证书核验已保存排程及主张的一致性，不证明机器时钟准确性或未观察转移内部的发生时刻。
