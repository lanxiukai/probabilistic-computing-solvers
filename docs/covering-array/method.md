# Fixed-row covering-array method

[简体中文](method.zh-CN.md) · [Overview](README.md) · [Report](report.md)

## Original problem and certificate

For fixed row count $N$, column count $k$ and alphabet size $v$, seek $A\in\{0,\ldots,v-1\}^{N\times k}$. The strength-two objective is

$$
E(A)=\sum_{i<j}\sum_{a,b=0}^{v-1}\mathbf{1}\!\left[\sum_{r=1}^{N}\mathbf{1}[A_{ri}=a,A_{rj}=b]=0\right].
$$

There are $\binom{k}{2}v^2$ required interactions. The search minimizes their missing count, without a QUBO penalty expansion or auxiliary problem variables. The released confirmation uses $v=3$; the implementation accepts $v\in\{2,3,4\}$. Unequal alphabets, strength above two and forbidden combinations are outside this evaluation.

An array is feasible exactly when its entries have the declared shape and alphabet and $E=0$. Independent certification enumerates every original column pair and takes a bit-set union of its observed symbol pairs. It does not infer feasibility from an incremental energy cache.

Every row supplies at most one symbol pair for a chosen pair of columns, so $N\ge v^2$. In this panel, only a successful $N=9,k=4,v=3$ array closes that lower bound and proves minimum row count. Success at another row count is a feasible construction upper bound. Failure within a budget is not a proof of impossibility.

## Persistent binary state and heat bath

Each cell stores $v$ one-hot binary entries $x_{r,c,a}$ with $\sum_a x_{r,c,a}=1$. One replica therefore has $Nkv$ model binary variables. Integer symbols, pair-count caches, best-state copies, random numbers and candidate weights are implementation storage, reported separately from model variables. The representation is a constrained binary-state simulation; its count does not imply an equal number of fabricated devices.

The selected block contains two distinct rows in one column. Conditional on all other cells, the kernel enumerates all $v^2$ joint symbol assignments. For candidate $z$, it evaluates the exact integer change $\Delta E_z$ and samples

$$
P(z\mid A_{\setminus B})=\frac{\exp[-\beta(\Delta E_z-\min_y\Delta E_y)]}{\sum_y\exp[-\beta(\Delta E_y-\min_y\Delta E_y)]}.
$$

Subtracting the minimum changes no probability. The selected route uses constant $\beta=8$, with FP64 weights and integer coverage counts. It updates the joint one-hot block, rather than treating its binary entries as independent draws. Duplicate pair-count removals and additions from the two rows are combined before evaluating a candidate's energy.

Updates are sequential within a replica and parallel across replicas. For the first $Nk$ steps the first cell follows a complete row-major sweep; afterward its position is sampled independently of the current values. The second row is a distinct state-independent choice. This guarantees that the scheduled first-cell sweep considers every cell if it completes. A visited entry means it was included in an update block, not that it flipped.

Each replica starts from independently uniform symbols generated by NumPy PCG64 using the declared seed. There is no constructive or classical optimization prefix, and no reference array enters initialization or proposals. Compilation and warmup use a separate disposable state. Finite-budget optimization with these updates does not establish equilibrium sampling accuracy.

## Controls and attribution

The matched Metropolis and plateau controls use the same initial arrays, block neighborhood, candidate-energy calculations, replica count and observation rules. Metropolis draws a uniform candidate and applies $\min(1,\exp[-\beta\Delta E])$. Plateau chooses uniformly among minimum-energy candidates; the current block is included, so equal-energy moves are allowed. These are update-rule controls. In particular, the Metropolis implementation still calculates all candidates and is not a specialized minimum-cost Metropolis solver.

ACTS Basic/IPOG is a separate classical constructive reference. It chooses its own row count $M$, and its original output is independently checked. A complete $M>N$ array remains a valid construction but fails the declared fixed-$N$ target. If $M\le N$, rows can be repeated without losing coverage, so the target is met. ACTS does not receive p-bit attribution.

Reduction from a replica's initial missing count establishes progress within its workflow. An ensemble minimum before and after search is also reported, but may involve different replicas. Heat-bath-specific benefit requires the matched controls; a better two-row neighborhood than a one-row neighborhood does not isolate a thermal effect. A plateau win or tie remains part of the conclusion.

The metadata field `physical_update_pbits_per_model` is $Nkv$ for heat bath and zero for classical controls. Its historical name denotes modeled entries assigned to this workflow. Actual block participation is measured separately by `visited`; neither field is a device count or proof of useful contribution.

## Deadline and evidence semantics

Every completed update chunk records current and best energy for every replica. A best state includes all accepted transitions inside that chunk, but its observation time has chunk resolution. Quality uses only chunks observed at or before `max_seconds` and, for a fixed-work replay, at or before `quality_max_step`. An overrun chunk is retained in returned-state evidence and excluded from eligible quality.

`best_values` is the best accepted state through all completed chunks; `quality_best_values` is the best deadline-eligible state. Initial/current/returned-best/eligible-best arrays are certified independently. A zero initial energy is an initialization success, not a discovery by heat-bath updates.

The final `visited` mask includes all completed chunks. A conservative per-replica lower bound for eligible participation is $\max(0,V_{\mathrm{final}}-2v(S_{\mathrm{total}}-S_{\mathrm{eligible}}))$, because a two-cell step can consider at most $2v$ binary entries. Final participation must not be presented as fully deadline-eligible without that distinction.

Public core traces retain every replica-best improvement, the first and last observations, and eligibility boundaries. Their original positions are stored as `curve_indices`. Omitted current-state fluctuations cannot be reconstructed from this curated trace. Fixed-work replay checks retained non-timing state equality and adds no independent trial.
