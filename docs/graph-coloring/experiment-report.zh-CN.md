# 图着色与列表着色的条件 p-bit 块更新

[English](experiment-report.md) | 简体中文

## 问题与价值

给定简单无向图、固定的 $K$ 种颜色及非空允许列表 $L_v$，最小化原图中的冲突边数：

$$H(c)=\sum_{\{u,v\}\in E}[c_u=c_v],\qquad c_v\in L_v.$$

零冲突是这个固定颜色目标的可证明基态。合法 $K$ 着色给出图色数的上界；没有找到 $(K-1)$ 着色不构成匹配的下界。如果另有独立核验的 $K$-clique，结合合法 $K$ 着色即可证明精确色数。

图着色表达冲突资源分配，在离散数学和计算中都有价值。采用的 DIMACS `fpsol2` 和 `inithx` 图族来自真实代码的寄存器分配；`le450` 是具有保证颜色目标的 Leighton 构造图。本实验针对公开图子问题，不将这些结果等同于完整编译器或调度系统的效果。[R1–R2]

## 表示与 p-bit 阶段

每条 GPU 链持续保存 $|V|K$ 个显式 one-hot 二元项 $x_{v,a}=[c_v=a]$。颜色标签和邻居颜色计数是缓存，独立核验会对照保存的位状态及原始边集检查它们。列表不允许的项固定为零。目标在这个受约束二元域上为二次式：

$$H(x)=\sum_{\{u,v\}\in E}\sum_{a=0}^{K-1}x_{u,a}x_{v,a}.$$

程序直接保持 one-hot 和列表约束，没有为每个 one-hot 约束实例化罚耦合。条件 p-bit 块枚举一个选中顶点的全部合法颜色，或多个顶点的全部合法颜色组合，再按 $\exp(-\beta H)$ 权重抽样。这是受约束二元热浴的 GPU 模拟。

单点和相邻双点更新支持任意颜色数；额外的三／四点路线限制 $K\le8$，枚举 $K^B$ 个赋值。顶点随机游走和重复顶点回退仅依赖输入图及独立随机数；内部边只计一次。局部能量用整数，条件权重用 FP64。在固定温度下，这些由输入决定的条件更新混合保持相应的受约束 Boltzmann 测度；循环优化日程不宣称输出已经平衡。

每条链在声明的允许列表内均匀初始化，不将参考着色读入初态。每个接受转移都可更新最优状态缓存，主机在块边界观测。跨时限块保留原始记录，但不计入时限内质量。

## 经典支撑与比较

标准着色可用结构 clique 消除全局颜色置换对称性。clique 仅从原图得到，逐对核对所需原始边，再将其顶点固定为互不相同的颜色。任意合法着色都能通过全局重命名满足这些固定。该规约保持零冲突解的存在性，不一定保持不可着色图上的最小正冲突值。一般列表限制没有这种全局对称性，所以列表输入禁用这一预处理。clique 构造属于经典支撑，时间、固定位和初始目标单列；初态已经零冲突不会获得 p-bit 新增命中。现代精确着色研究也采用这一标准规约。[R5]

可选交换蒙特卡罗路线使用固定逆温度梯度，相邻标签以

$$\min\{1,\exp[(\beta_i-\beta_j)(H_i-H_j)]\}$$

接受交换。温度标签移动，二元状态留在原有链中，等价于在固定温度槽之间交换状态。同一梯度组中的链相互耦合；独立实验单位是梯度组，而不是每个温度槽。交换步骤是条件 p-bit 更新的经典支撑。[R6–R7]

匹配 Metropolis 和随机平局最小能量下降（`plateau`）使用同样的二元表示及允许块。独立单线程 C++ TabuCol-style 实现提供更广的经典参照，使用冲突顶点、增量计数、随机禁忌期和改进最优值的特赦。这是参考 TabuCol 思路的自有实现，不是对外部 HEAD 的复现。[R3–R4] 多链 GPU 与单线程 CPU 使用相同搜索秒数，不等于资源相同或已建立加速。

PT 与 plateau 对照评估的是完整路线：plateau 不使用温度交换，因此两者的差异本身不能将条件 p-bit 核的贡献与交换支撑分离。

## 时间、规模与证据口径

准备、有界搜索及完整 runner 时间分别测量。搜索包括运行中的 checkpoint 和曲线写入开销；完整 runner 还包括最终认证与输出写盘。首次零冲突时间是合格块边界上的观测，不是块内精确命中时刻。GPU 分配器峰值不包含完整 CUDA 上下文及驱动占用；设备与软件版本绑定在每项测量记录中。

原始 `fpsol2.i.1` 有 496 顶点，其中 227 个为孤立点。65 色表示为每条链实例化 32,240 位，其中 17,485 位连接原始冲突因子。固定经独立核验的 65-clique 后，自由允许坐标为 28,015，其中连接原始冲突因子的为 13,260。原始 `inithx.i.1` 有 864 顶点、18,707 边和 345 个孤立点；54 色表示实例化 46,656 位，其中 28,026 位连接原始冲突因子。固定已核验的 54-clique 后，自由坐标为 43,740，其中连接这些因子的为 25,110。这些是已审计的输入／模型计数，本身不证明某次搜索成功。

“与冲突因子相连”按原图邻接关系计数，不是 clique 固定后剩余自由变量之间的耦合数。访问掩码标记每个被更新访问的顶点的全部允许 one-hot 坐标，不表示每个被标记的位都发生过翻转。另存的 `changed` 计数是联合块赋值改变的次数，不是不同翻转位的数量。上述任一模型规模本身都不能证明成功求解了 32K 全相互作用位实例。

## G3独立确认

冻结确认使用2026102351和2026102352两个新种子，每次原生调用128链；共56次自然调用（18次热浴、18次plateau、20次单线程Tabu）及4次不增加试验的回放，无失败或未执行项。开发图为le450_5a、le450_25c和fpsol2.i.1；le450_5b、le450_25d、fpsol2.i.2、inithx.i.1及独立列表实例用于留出确认，策略在结果出现前确定。第二种子的执行顺序反向，全部结果保留。

## 已审计的实现等价性试测

G2A 比较有界整数能量差的 FP64 Boltzmann 权重缓存与直接指数运算，以及准备复用与全新准备。8 次调用使用种子 `2026102341`、128 条链、每块 512 步、每链 65,536 步，全部在 120 秒保护上限内完成指定工作。5 对比较的全部 31 或 32 个非时间状态数组逐项完全一致，初态及初始／最终 checkpoint 数组也完全相同。独立全量状态审计核验了 10,240 个保存颜色赋值。这些实现比较不增加独立质量确认试验。

| 缓存比较 | 搜索秒数：关闭 → 开启 | 完整运行秒数：关闭 → 开启 | 两次调用的冲突数 |
|---|---:|---:|---:|
| `le450_5a`，四顶点块／温度交换 | 0.8403 → 0.7029 | 4.6808 → 4.7363 | 7 |
| `le450_25c`，双顶点块／温度交换 | 0.5529 → 0.4468 | 5.9349 → 5.7532 | 20 |
| `fpsol2.i.1`，65-clique／单顶点恒温 | 0.2217 → 0.1392 | 4.4939 → 4.4762 | 0 |

准备复用使 `le450_5a` 的实测准备时间由 3.0836 秒降至 2.8576 秒，`fpsol2.i.1` 由 2.7701 秒降至 2.2326 秒，确定性状态保持相同。这些观察支持在后续开发中采用两项选项。每组比较只有一次顺序计时，完整运行时间的变化并不一致，不能据此建立稳定的端到端加速优势。

## 证据边界

原始 DIMACS 图与生成的列表着色示例分属不同输入类别。合成示例有 256 顶点、2,245 边、4 种颜色，每个顶点允许 3 色；1,024 个实例化坐标中有 768 个自由允许坐标。构造时的 planting 见证仅用于核验，不作为求解器输入；该示例不证明一般列表着色难度。

发布必须将每项已验收测量绑定到源码、配置、原始输入身份、初态、RNG 起止状态及独立核验的见证。完整初态／终态、时限内与返回的最优状态、周期 checkpoint、逐块写入的曲线及全部温度交换随机数都保留。搜索预算内的 checkpoint 和曲线开销计入搜索壁钟。可恢复 checkpoint 是证据，不宣称已经实现自动续跑。

当前细化针对结构对称性、低色数块宽、温度交换、副本利用和 checkpoint 开销；其新种子和留出实例确认结果及未命中均已列出。历史颜色参考值不是当前求解器排名，软件可行性结果也不等于物理 p-bit 硬件测量。
